# Compact ClickUp card template

## Draft ID and requested system area

One sentence describing the user outcome.

### Work

- Concrete behavior and affected data.
- Relevant validation, permissions and lifecycle.
- Output and observable acceptance.

### propose API contracts

Omit when no API is involved. For each proposed endpoint, include method/path, purpose, source and side effects, authorization/validation, request, response and separate error conditions. Mark verified existing contracts as current instead.

### Example and required inputs

Use consistent fictional or redacted data. Keep complete relevant contracts inside the card.

### Acceptance, dependencies and effort

Include observable checks, owner, shared work and estimate basis when requested.

### Unresolved decisions and source

| Question/input | Impact/dependent step | Owner/source |
| --- | --- | --- |

Use actual canonical ClickUp links in live cards. Offline examples identify fixture filenames explicitly. No local-spec dependency for live card readers.
