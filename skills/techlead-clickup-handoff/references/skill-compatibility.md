# Supplementary skills and local adaptation

All linked supplements ship in this kit as real files. Read only the method needed for the requested output.

| Skill | Use | Boundary |
| --- | --- | --- |
| [to-prd](../../to-prd/SKILL.md) | Synthesize a local PRD from available context | Kit adaptation produces drafts only; no interviews, tracker setup, labels or writes |
| [to-issues](../../to-issues/SKILL.md) | Dependency planning and independently verifiable slices | Kit adaptation produces local issue drafts; preserve requested layer-specific cards |
| [domain-modeling](../../domain-modeling/SKILL.md) | Resolve ambiguous terms, entities and invariants | Keep glossary/decisions in the agreed local artifact; no mandatory repository files |
| [codebase-design](../../codebase-design/SKILL.md) | Interfaces, ownership and testability | Inspect code only when available and in scope; no automatic implementation |

The installed source also named pstack:architect and a platform skill. They are optional and not bundled. The core templates can satisfy ordinary local planning without them. Discover any separately installed skill from the current catalog. Never use a version-pinned or personal path.

Pass the current write scope, confirmed decisions, language, requested granularity and known owners to each supplement. Use only compatible drafting methods if an independently installed version publishes automatically. Names alone do not prove identical behavior. Do not modify shared installed skills.
