# Client change-impact checklist

Read [shared policy](../techlead-analyse-clickup/references/shared-policy.md).

## Input

Old-to-new request, approved baseline/source, users/accounts/channels, effective date and available system/data evidence. Use [collect](../techlead-clickup-collect/SKILL.md) for missing source content or [rebrief](../techlead-clickup-rebrief/SKILL.md) for unclear outcome.

## Work / output

Lead with a usable checklist: clarify baseline/request, inspect affected behavior/data/integrations/permissions/history, classify with evidence, then determine what can be promised and what needs assessment.

Separate approved configuration, correction to baseline, new behavior and pending assessment. Number of fields/screens/hours does not prove low impact. Assess related changes together.

When requested, include many relevant examples and identical wording with different impact: future-only vs backfill, label vs persisted identifier, local value vs external contract, one account vs cross-tenant access, suggestion vs automatic action.

Unknown is not no-impact. Give pending questions owner/impact/next response/affected commitment. Do not reopen approved behavior/authority; new scope/price/date needs its decision and delivery evidence.

Write the local checklist or requested standalone guidebook. Fold longer examples/references when supported; use ClickUp requirement links. Check that BA/PO can decide the next action from it. Publishing/sending requires its own authorization.
