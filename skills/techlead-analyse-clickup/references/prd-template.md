# PRD template

## Problem and outcome

Name the users, problem, proposed solution and measurable success. Link evidence and distinguish assumptions.

## Goals and exclusions

Record agreed scope and explicitly excluded behavior. Do not infer exclusions from missing information.

## Requirements

| ID | User need/behavior | Priority | Source/status | Observable acceptance |
| --- | --- | --- | --- | --- |

## Flows, design and interfaces

Describe happy, alternate, empty, error and permission states. Include relevant data and interface requirements. Mark new contracts as proposals. Formal enterprise documentation is scope only when requested.

## Testing, dependencies and open questions

Record test evidence, ownership, decisions, impact and dependent steps. This is a local review draft, not an approval or publication receipt.
