# Specs template

## Implementation and behavior

Describe the scoped implementation and verified current state. Separate proposed behavior from existing contracts.

## Interfaces and data

Include relevant methods/paths, inputs, responses, errors, validation, authorization, pagination, retry/idempotency, data ownership, lifecycle and retention. Omit irrelevant sections. Do not invent existing APIs.

## Verification and operations

State observable acceptance, test data, error cases, monitoring, migration, rollout and rollback where relevant. Record inputs that block only the affected integration, acceptance or release step.

## Decisions and sources

Use source/status/owner for unresolved items. Delivery cards must contain their complete relevant contracts without depending on this local document.
