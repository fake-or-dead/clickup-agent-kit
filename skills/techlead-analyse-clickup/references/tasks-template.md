# Task draft template

## Outcome and scope

Name the outcome, source baseline, requested granularity and current readiness. Local drafts do not imply development approval.

## Card

- Local draft ID and title.
- User outcome and concrete work.
- Inputs, outputs, rules, permissions and relevant contracts.
- Observable acceptance and QA notes.
- Owner and dependencies.
- Estimate range/basis, if requested. Hours per person-day must be supplied for conversion.
- Confirmed decisions and source links.
- Unresolved question/input, owner, impact and dependent step.

Repeat only for requested cards. Count shared work once. Identify preparation, implementation and documentation effort without hiding their project cost. Preserve requested backend/frontend granularity; use end-to-end slices when requested or appropriate.

## Sequence and publication boundary

List dependencies and independent work. Exact destination, approved content and operation are prerequisites for a separate publish request. Do not set labels, estimates, assignees or ready status unless those fields are authorized.
